# تشغيل التطبيق من ملف الزيب — Running from the zip

> **الأهم أولًا:** ملف الزيب هو **كود المصدر**، وليس تطبيقًا جاهزًا يُفتح بالنقر.
> فكّ الضغط لا يشغّل شيئًا، والخريطة والأخبار لا تظهر — لأنه لم يُبنَ ولم يعمل بعد.
>
> **First, the thing that matters:** the zip is **source code**, not an app you
> double-click. Unzipping it runs nothing, and the map and the news will not
> appear — because nothing has been built or started yet.

---

## لماذا؟ / Why

هذا التطبيق **خادم + متصفّح** (Next.js). نصفه يعمل على خادم يقرأ أكثر من ١١٩ مصدرًا
حيًّا، ونصفه في المتصفّح. فكّ الضغط يعطيك النصف الأول كنصوص برمجية فقط. لتشغيله
لا بدّ من ثلاث خطوات: تثبيت الاعتماديات، البناء، ثم التشغيل.

This is a **server + browser** application (Next.js). Half of it runs on a server
that reads 119+ live sources; half runs in the browser. Unzipping gives you the
first half as text. Three steps turn it into a running product.

---

## ١) على جهازك / On your machine

تحتاج **Node.js 20 أو أحدث**.

```bash
unzip lambda-nx-<sha>-studio.zip -d lambda-nx
cd lambda-nx

npm install          # يثبّت الاعتماديات — أول مرة فقط، وقد تأخذ دقيقتين
npm run build        # يبني التطبيق
npm start            # يشغّله على http://localhost:3000
```

للتطوير مع إعادة التحميل التلقائي: `npm run dev`.

---

## ٢) لماذا لا تعمل الخريطة والأخبار بلا خطوة أخرى؟

تعمل **فورًا** — البوّابات والخريطة والأخبار كلها بلا مفاتيح ولا حساب (الميثاق §1).
إن ظهرت فارغة فالسبب أحد ثلاثة، وكلها يقولها التطبيق عن نفسه في `/api/health`:

| العَرَض | السبب | الحل |
|---|---|---|
| الخريطة فارغة، «Reading the live feeds…» لا ينتهي | لا اتصال بالإنترنت من الخادم | تحقّق من الشبكة والوكيل (proxy) |
| المصادر «تفشل» جميعًا | جدار ناري يمنع الطلبات الصادرة | افتح HTTPS الصادر |
| الحسابات والحفظ لا يعملان | لا قاعدة بيانات | اضبط `DATABASE_URL` — انظر أدناه |

---

## ٣) قاعدة البيانات — ما الذي يعتمد عليها فعلًا

**البوّابات والخريطة والأخبار لا تحتاجها إطلاقًا.** تحتاجها هذه فقط:

- الحسابات (Pi وخارج Pi)، وحفظ التحقيقات، والمجموعات، والمنشورات
- **حفظ تفضيلات المستخدم عبر الأجهزة** — بلا قاعدة بيانات تبقى محفوظة في
  المتصفّح فقط، وهذا يكفي لمعظم الاستخدام

```bash
# .env.local
DATABASE_URL=postgresql://user:password@host:5432/lambda_nx
SESSION_SECRET=$(openssl rand -base64 32)
```

ثم طبّق الترحيلات — وهذا ما يبني الجداول من الصفر على أي Postgres:

```bash
npm run db:migrate
```

للتحقّق أنّ كل شيء موصول فعلًا:

```bash
curl http://localhost:3000/api/health?deep=1
```

يردّ بحالة كل جزء: الاتصال، الجداول الموجودة، وعدد الترحيلات المطبَّقة مقابل التي
يشحنها هذا البناء. لا يُظهر أي سرّ — قيم منطقية وأسماء مزوّدين فقط.

---

## ٤) المتغيّرات — أين توضع

**لا تُوضع في أي ملف داخل المستودع أبدًا.** انظر «قاعدة المالك» في
[`docs/SECURITY.md`](./SECURITY.md): السرّ يعيش في مخزن المالك وحده — لا في
commit، ولا في وثيقة، ولا يصله أي مساهم يُضاف للمستودع.

- **محليًا:** ملف `.env.local` (مستثنى من git، ولا يدخل الزيب أبدًا — الحزّام
  يفشل البناء لو حاول)
- **على Netlify / Vercel:** لوحة متغيّرات البيئة الخاصة بالمشروع
- **الأسماء فقط** موجودة في `.env.example` — بلا قيم

## ٥) نسختا الزيب / The two zip profiles

| النسخة | الحجم | ما فيها |
|---|---|---|
| `lambda-nx-<sha>.zip` | ~١٤٣٠ ك.ب | كل شيء: الاختبارات، الوثائق، لقطات الترحيلات |
| `lambda-nx-<sha>-studio.zip` | ~٩٥٥ ك.ب | ما يُثبَّت ويعمل فقط — تحت حدّ الميغابايت في Pi App Studio |

النسخة المصغّرة **تُبنى وتعمل بالكامل** — لا ينقصها شيء من التطبيق. المحذوف منها
هو الاختبارات والوثائق ولقطات أداة الترحيل، وكلها باقية في المستودع.

```bash
npm run package          # النسخة الكاملة
npm run package:studio   # نسخة Pi App Studio
```

الحدّ مفروض في الكود: فوق الميغابايت يفشل البناء ويقول ما يجب تقليصه، وفوق ٩٠٪
يحذّر بالمساحة المتبقية.
